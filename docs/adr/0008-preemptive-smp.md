# ADR-0008：抢占式对称多处理调度

- 状态：**已接受**
- 日期：2026-11-03
- 关联：[执行模型](../execution.md)、[总体架构](../architecture.md)

## 背景

微内核需要可预测的线程调度、IPC 阻塞/唤醒与 SMP 支持。服务器与 POSIX 线程共享调度器。

## 决策

1. **抢占式**调度：中断返回、时间片耗尽、IPC 阻塞触发切换。
2. **对称多处理**：所有 CPU 同等参与；BSP 启动 AP。
3. **每 CPU run queue**：32 个固定优先级 + 同优先级轮转。
4. **Tickless**：一次性定时器到“时间片结束/下一唤醒”的较早者。
5. 默认时间片 4 ms；优先级 0 最高，31 为 idle。
6. **亲和性**：`CpuMask` 限制可运行 CPU。
7. **负载均衡**：idle CPU 拉取 Runnable TCB。
8. **IPC 调度**：Endpoint 等待队列按优先级与 FIFO 排序；Notification 唤醒。
9. **故障隔离**：线程故障通过 Fault Endpoint 交给 POSIX Server；内核不变量破坏时停机。

## 后果

**收益**

- 交互响应好；IPC 阻塞/唤醒与调度自然配合。
- 多核利用率高；适合 QEMU/真机 SMP。
- POSIX 线程与服务器共享同一调度模型。

**成本与取舍**

- 并发复杂度高：锁、竞态、优先级反转、IPI。
- 需要确定性模拟与压力测试。
- 1.0 采用固定优先级；优先级继承属于后续版本。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 协作式调度 | 简单；死循环占住 CPU。 |
| 主从多核 | 实现直接；扩展性受限。 |
| 实时调度 | 适合硬实时；核心复杂度上升。 |

## 架构一致性检查

- TCB 是唯一调度单位；POSIX 线程映射到 TCB。
- IPC 阻塞/唤醒通过 Endpoint/Notification。
- 中断上半部使用固定分配与自旋锁。
