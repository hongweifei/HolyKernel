# ADR-0006：用户态 VFS 与 Path Server

- 状态：**已接受**
- 日期：2026-11-03
- 关联：[VFS 与 Path Server](../vfs.md)、[服务器](../servers.md)、[POSIX 与 libc](../posix.md)、[HolyFS](../holyfs.md)

## 背景

POSIX 应用需要统一路径空间与文件语义；Holy 原生客户端需要文档身份、集合、修订与盘符；具体文件系统（ext4、HolyFS、tmpfs、devfs、procfs）具有不同实现。内核保持最小，文件系统、路径解析与 POSIX 投影都放在用户态。

## 决策

1. **VFS Server** 作为用户态服务运行，维护 Holy 原生命名空间：盘符、`DocId`、集合、修订、文档令牌与文件系统后端。
2. **Path Server** 作为独立用户态服务运行，维护路径解析、dentry/inode、文件句柄与页缓存，并把 VFS 盘符投影为 POSIX 路径。
3. 文件系统以 **FS Backend** 接入：ext4 由独立 `hk-server-ext4` 通过 Block Endpoint 挂载，HolyFS 由独立 `hk-server-holyfs` 提供；VFS 通过远程 Holy 后端访问两者。tmpfs、devfs、procfs 作为内建后端留在 VFS 进程内。
4. POSIX Server 维护 fd 表；fd 指向 Path Server 的 `FileHandle`。
5. 文件数据通过共享 **Frame** 传输；Path Server 与 VFS 传递 Handle 与元数据。
6. 盘符映射：`E:` 由 `hk-server-ext4` 提供，`T:`/`D:`/`P:` 由 VFS 内建后端提供；HolyFS 提供 `H:`/`I:`。Path Server 默认把 `T:` 投影到 `/` 与 `/tmp`，`vfs.root=ext4` 时把 `E:` 投影到 `/`，其余盘符投影到 `/disk`、`/disk-I`、`/dev`、`/proc`。
7. 权限检查使用 POSIX Server 传入的凭证；Path Server 与 VFS 在边界执行属主/权限位检查。
8. VFS 或 Path Server 崩溃后由 Root Server 重启；在途请求返回 `EIO`，客户端重连并按策略重建句柄。
9. 文件系统、路径解析与 POSIX 投影位于用户态；内核提供 HMP、Endpoint 与 Handle。

## 后果

**收益**

- Holy 原生命名空间与 POSIX 路径空间各自清晰：VFS 管理文档身份，Path Server 管理路径与 fd。
- 多文件系统后端可插拔；ext4 与 HolyFS 独立重启，VFS 只按服务名重连。
- 页缓存通过 Frame 共享，读路径可零拷贝。
- POSIX Server 保持进程与 fd 语义，路径投影集中在 Path Server。

**成本与取舍**

- 每次文件操作经过 POSIX Server → Path Server → VFS → 后端 IPC；ext4 多一跳服务边界，需要缓存与批处理。
- VFS 与 Path Server 两个重启点，需要分别处理句柄重建与错误传播。
- 页缓存一致性需要与后端修订协调。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 内核内 VFS | 性能直接；内核膨胀，可信基扩大。 |
| POSIX Server 内 VFS 库 | 组件少；VFS 与 POSIX 耦合，重启粒度粗。 |
| 单个用户态 VFS | 结构简单；Holy 命名空间与 POSIX 路径语义耦合。 |
| VFS + Path Server | 职责清晰；IPC 成本与重连路径增加。 |

## 架构一致性检查

- VFS 与 Path Server 都是用户态服务，通过 Endpoint 与 POSIX Server/FS Backend 通信；ext4 与 HolyFS 是独立 FS Backend 服务。
- 文件数据通过 Frame 共享。
- 内核提供 Task/TCB、Cadence/Meter、HMP（Arena/Capacity/Frame/Region）与 Handle。
- HolyFS 以独立服务提供 `H:`/`I:`，VFS 通过远程后端访问。
