# ADR-0006：用户态 VFS

- 状态：**已接受**
- 日期：2026-11-03
- 关联：[VFS](../vfs.md)、[服务器](../servers.md)、[POSIX 与 libc](../posix.md)

## 背景

POSIX 应用需要统一路径空间与文件语义；具体文件系统（ext2/ext4、HolyFS、tmpfs、devfs、procfs）具有不同实现。内核保持最小，文件系统与路径解析适合放在用户态。

## 决策

1. VFS 作为**用户态服务器**运行，负责挂载表、路径解析、dentry/inode 缓存、文件句柄与页缓存。
2. 文件系统以 **FS Backend** 服务器接入：ext2/ext4、HolyFS、tmpfs、devfs、procfs。
3. POSIX Server 维护 fd 表；fd 指向 VFS `FileHandle`。
4. 文件数据通过共享 **Frame** 传输；VFS 与后端只传 Handle 与元数据。
5. 挂载点由 VFS 维护；`/`、`/dev`、`/proc`、`/tmp` 初始挂载；`/` 可为 ext2/ext4 或 HolyFS。
6. 权限检查使用 POSIX Server 传入的凭证；VFS 与后端共同执行。
7. VFS 崩溃后由 Root Server 重启；进行中请求返回 `EIO`，客户端重连并重建句柄。
8. VFS、路径解析与文件系统逻辑位于用户态；内核提供机制。

## 后果

**收益**

- 路径空间与文件语义统一；多文件系统后端可插拔。
- VFS 与后端可独立重启；文件系统实现隔离。
- 页缓存通过 Frame 共享，读路径可零拷贝。
- POSIX Server 保持文件逻辑集中在 VFS。

**成本与取舍**

- 每次文件操作经过 POSIX Server → VFS → 后端 IPC；需要缓存与批处理。
- VFS 重启需要句柄重建与错误传播。
- 页缓存一致性需要与后端协调。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 内核内 VFS | 性能直接；内核膨胀，可信基扩大。 |
| POSIX Server 内 VFS 库 | 组件少；VFS 与 POSIX 耦合，重启粒度粗。 |
| 独立 VFS Server | 解耦清晰；IPC 成本增加。 |

## 架构一致性检查

- VFS 是用户态服务，通过 Endpoint 与 POSIX Server/FS Backend 通信。
- 文件数据通过 Frame 共享。
- 内核只提供 VSpace/Frame/Handle。
